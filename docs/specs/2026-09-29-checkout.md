# Módulo orders: checkout y pago (Fase 2b de las features)

## Metadatos
- Fecha: 2026-09-29
- Módulo de dominio: orders (nuevo; consume las API públicas de `events` y `tickets`)
- Requerimiento: ver `2026-09-29-event-search.md`. Esta spec cubre la pantalla **5 · Checkout y pago** (escritorio y móvil) y el traspaso de la selección desde la pantalla de entradas.

## Objetivo
Al pulsar "Continuar" en `/events/[slug]/tickets`, la selección se guarda en un store y se abre `/events/[slug]/checkout`, que muestra: pasos (1 ✓, 2 activo, 3), aviso de reserva con cuenta regresiva de 10:00, datos del comprador, método de pago (Tarjeta / Yape / PagoEfectivo, con los campos o el mensaje de cada uno), aceptación de términos y el resumen con "Cambiar entradas" y "Pagar S/ xx". Al pagar se valida con zod, se crea un pedido mock y se navega a la confirmación. Todo simulado: no se envía nada a ningún servidor.

## Fuera de alcance
- Pantalla de confirmación (spec `2026-09-29-order-confirmation.md`): esta spec solo navega a `/events/[slug]/confirmation`.
- Pago real, pasarela, QR de Yape o código de PagoEfectivo reales.
- Login: el checkout es como invitado.
- Liberar asientos en el mapa cuando vence el temporizador (no hay backend).

## Criterios de aceptación
- **AC-1**: `buyerSchema` y `paymentSchema` aceptan datos válidos y rechazan: email inválido, DNI de 7 dígitos, celular que no empieza en 9, tarjeta que no pasa Luhn, vencimiento pasado, CVV de 2 dígitos y términos sin aceptar; con Yape o PagoEfectivo no se piden datos de tarjeta.
- **AC-2**: `startCheckout` guarda el borrador con `expiresAt` a 10 minutos; `placeOrder` crea un pedido con id `TK-` + 5 dígitos, total y líneas del borrador, método y últimos 4 dígitos (sin número completo ni CVV en el estado), y vacía el borrador.
- **AC-3**: flujo en navegador: elegir entradas → "Continuar" → el checkout muestra las mismas líneas y el mismo total; enviar vacío marca los errores y enfoca el primero; con datos válidos y términos aceptados "Pagar S/ xx" navega a `/events/{slug}/confirmation`. Recargar el checkout mantiene la selección; entrar sin selección muestra el estado vacío.
- **AC-4**: a 390 px no hay scroll horizontal y el resumen es plegable; en ≥ 1024 px el resumen está a la derecha. `npm test`, `npx tsc --noEmit`, `npm run lint` y `npm run build` sin errores.
